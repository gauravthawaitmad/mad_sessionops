# Part 1 — Milestone Overview

## Production goal

At the end of M2, a Community Officer can fully build out a school's structure and enroll children:

- Operate within a single locked academic year ("2026-2027") that is platform-wide active
- Add classes (5th, 6th, 7th, 8th from a global catalog) to a school
- Add sections (A–L) under each class
- Enroll children, capturing required and optional info
- Edit children — including moving them between sections (with history preserved)
- Deactivate children with a mandatory removal reason captured in an audit log
- Reactivate previously-deactivated children
- Filter the children list by section, class, status, and search

The Structure tab and Children tab are both active in M2. The other tabs (Volunteers, Slots, Calendar) are visible but show "Coming soon."

## Key architectural decisions

### 1. Three-state soft delete pattern (M2-specific)

M2 introduces a dual-flag soft delete pattern that differs from M1 models:

| `is_active` | `removed` | Meaning |
|-------------|-----------|---------|
| `true` | `false` | Active, current record |
| `false` | `false` | Archived (preserved for history; not in active queries) |
| `false` | `true` | Soft-deleted (treated as deleted by app, preserved in DB) |
| `true` | `true` | Not possible |

Plus `deleted_at` timestamp set when `removed` becomes `true`. This differs from M1's single-flag pattern. Documented in `DECISIONS.md` as a deliberate departure justified by year-progression history needs.

### 2. Audit fields on every M2 domain model

`created_at`, `updated_at`, `deleted_at`, `created_by FK User`, `updated_by FK User`.

### 3. AcademicYear is real; admin-only

Build the full model, build the admin-only UI, seed 2026-2027 as active. CO's UI shows year as locked-in text.

### 4. Class is a global catalog

~12 rows in the system, seeded once. CO doesn't create classes — they pick from the catalog. Each `Class` belongs to a `Program`.

### 5. Program is a real table for future flexibility

M2 seeds one row: "Foundation Program". `Class` and `ChildProgram` both FK to it. No Program management UI in M2.

### 6. Section is hardcoded as A–L

No global Section table. `class_section.section_code` directly stores the letter. The list is a code constant.

### 7. Multi-table child enrollment is intentional history scaffolding

Five tables (`Child`, `ChildClass`, `ChildClassSection`, `BatchChild`, `ChildProgram`) exist to support history preservation across year progression. Learned from the existing Bubble system.

### 8. School identifier convention

M2 tables use `school_id` as FK column name, but it's an FK to `partner.partner_id`. Documented; do not rename `Partner`.

### 9. Hard cap on children per school

Via `partner.confirmed_child_count`. When a CO tries to add a child, system checks active child count. Hard block at limit. If `null`, treat as unlimited.

### 10. Section capacity max 5 children

Application level, not DB. Per business rule R1.

## F-M2-4 — Classes

**What:** Global Class catalog seeded with 5th, 6th, 7th, 8th. Program catalog seeded with "Foundation Program". CO selects from catalog when adding a class to a school. Each addition creates a `SchoolClass` row. CO cannot delete a class if it has active children enrolled.

**Correction (found and fixed post-M6):** This section originally said "CO cannot delete a class if it has active sections," enforced by `soft_delete_school_class` checking for active `ClassSection` rows referencing the class. M6 decoupled classes from sections/buckets — buckets never set `school_class_id` (M6 decision #1), and class assignment moved to a direct `ChildClass` link (F-M6-4) — so that check became dead code: a class with active enrolled children but zero sections could be deleted, silently orphaning those children's class assignment. Fixed to check active `ChildClass` rows instead. See M6.md's F-M2-4 addendum for the fix details.

**Who uses it:** CO, Admin

**Business rules enforced:**
- Cannot add the same class twice to the same school in the same academic year (409)
- Cannot delete a class with active children enrolled (409) — corrected post-M6, see above
